# 方案：工具调用展示

> 状态：方案稿，待审核，未写代码。

## 一、目标

DSH 最大的卖点是「agent 会动手」——跑命令、读文件、上网。现在 `chat.vue` 把 `tool-call` / `tool-result` 全过滤了，用户只能看到最后一段文字，等于把远程控制降级成了聊天机器人。本方案把工具调用渲染成卡片，让「agent 在干嘛」可见。

## 二、协议事实（已确认）

1. **历史数据早就解析好了**：`history.ts` 的 `toBubbles()` 已经把事件流转成了 part，类型也已定义：

```ts
type AssistantPart =
  | { kind: 'text'; text: string }
  | { kind: 'tool-call'; name: string; args: string }        // 工具名 + 参数
  | { kind: 'tool-result'; text: string; isError?: boolean } // 结果 + 是否失败
  | { kind: 'system'; text: string }
```

2. **唯一缺口是渲染**：`chat.vue` 的 `bubbleText()` 里 `filter(p => p.kind === 'text')` 把 tool-call/tool-result/system 全丢了。

3. **流式里也有工具帧**：`assistant-stream` 的 `chunk` 类型包含 `tool-call-delta`（当前 `handleAssistantStream` 只处理了 `text-delta`，其余忽略）。

4. 事件对应关系（`history.ts` 里）：`tool/call` 事件 → tool-call part，`tool/result` 事件 → tool-result part。

## 三、实现步骤

1. **历史渲染**（改 `chat.vue` 的气泡渲染，不再用 `bubbleText()` 拼接）
   - 遍历 `bubble.parts`，按 kind 分别渲染：
     - `text` → `<markdown-view>`
     - `tool-call` → 工具卡片（工具名 + 参数）
     - `tool-result` → 结果卡片（成功绿 / 失败红）
     - `system` → 灰色小字
   - 新增 `tool-card` 组件（可折叠：默认收起参数，点开看详情）。

2. **流式渲染**（改 `handleAssistantStream`）
   - 处理 `chunk.type === 'tool-call-delta'`：实时把工具调用名/参数追加到一个「进行中的工具卡片」。
   - 工具开始 → 显示「⏳ 正在调用 xxx」；`tool/result` 到达 → 标为成功/失败。

3. **卡片设计**

```
┌──────────────────────────────┐
│ 🔧 run_shell_command          │  ← 工具名（一行）
│    {"command": "ls -la"}      │  ← 参数（可折叠）
│    ✓ 执行成功                  │  ← 结果状态
│    total 12 ...               │  ← 结果内容（可折叠）
└──────────────────────────────┘
```

## 四、待确认（实现时核对）

1. **`tool-call-delta` 的确切结构**：需要读 DSH 源码确认 `chunk` 里 tool-call-delta 的字段（是增量 delta 还是完整快照、有没有 callId/toolName）。这决定流式工具卡片怎么拼。
2. **工具结果的内容格式**：`tool-result` 的 `text` 是 `textOf(d?.message?.content)` 提取的，长结果要不要截断 + 「展开」按钮。

## 五、与审批功能的耦合

工具调用展示是**审批功能的前置**：审批卡片（`approval/asked`）就出现在某个 `tool/call` 的位置。建议顺序：先做工具展示，再做审批。

## 六、边界

- 一期：渲染 tool-call / tool-result 为可折叠卡片，成功/失败着色。
- 不做：工具调用中途的取消、重试、编辑参数（那是 DSH 桌面 GUI 的高级功能）。
