# 方案：上传图片（识图）

> 状态：方案稿，待审核，未写代码。

## 一、目标

聊天输入框支持上传图片，随文字一起发给 DSH（DSH 有识图能力，模型支持 vision）。App 端选相册/拍照，H5 端选文件。

## 二、协议事实（已从 DSH 源码确认）

1. `session/prompt` 的 `content` 是数组，支持三种单元：

```ts
type PromptContent =
  | { type: 'text'; text: string }
  | { type: 'image'; mediaType: 'image/png'|'image/jpeg'|'image/webp'|'image/gif'; data: string; name?: string }
  | { type: 'file'; receiptId: string }
```

2. **图片是 base64 内嵌**（`data` 字段直接传 base64），**不需要先上传**——只有 `file` 才需要先上传拿 `receiptId`。所以这个功能比想象简单。

3. 图片限制在 projections 的 `imageLimits` 里（Host 全局下发）：

```ts
imageLimits: {
  maxImageBytes: number          // 单图最大字节
  maxImagesPerMessage: number    // 一条消息最多几张图
  maxMessageImageBytes: number   // 一条消息图片总字节
  maxImagePixels: number         // 单图最大像素
  maxImageDimension: number      // 单图最大边长
  mediaTypes: ('image/png'|'image/jpeg'|'image/webp'|'image/gif')[]
}
```

4. 已支持的类型：png / jpeg / webp / gif（`mediaTypes` 白名单）。

## 三、实现步骤

1. **选图**
   - App 端：`uni.chooseImage({ count, sizeType: ['compressed'] })`，返回 `tempFilePaths`。
   - H5 端：`<input type="file" accept="image/*">` + `FileReader`。

2. **读成 base64**
   - App 端：用 `plus.io` 读文件，或 `uni.getFileSystemManager().readFile({ encoding: 'base64' })`。
   - H5 端：`FileReader.readAsDataURL`，取 `data:` 后面的 base64 段。

3. **校验 imageLimits**（超限不报错兜底，而是选图后立即校验并提示，符合「少兜底」原则）
   - 从当前会话 projections 拿 `imageLimits`（来源见「待确认」）。
   - 校验：字节数、像素、边长、类型白名单；超限直接 `showToast` 拒绝，不上传。

4. **发送**
   - `client.ts` 的 `sendPrompt` 扩展：`content: [ {type:'text', text}, {type:'image', mediaType, data, name} ]`。
   - 现在 `sendPrompt(sessionId, text)` 只传 text，要改成接受 content 数组。

5. **气泡渲染**
   - 用户气泡里显示图片缩略图（`<image>` 标签），下方是文字。

## 四、待确认（实现时核对）

1. **imageLimits 从哪拿**：目前 App 只订阅了 `session/follow`，没订阅 `session/control`（projections 是 control 流下发的）。需确认：是从 `session/list` 返回的 projections 里取，还是需要额外订阅 control 流。倾向：先从 list 的 projections 拿（已有），不够再订阅 control。

2. **base64 读取的性能**：大图 base64 可能几 MB，App 端需用 `sizeType: ['compressed']` 压缩；若压缩后仍超 `maxImageBytes`，需要端上再降采样（canvas 缩放）。这一步 App 端实现成本较高，可作为二期。

3. **多图**：`maxImagesPerMessage` 允许多图，一期先支持单图，多图二期。

## 五、边界

- 一期：单图 + 文字，png/jpeg 为主，App 端压缩。
- 不做：文件上传（`receiptId` 那套），那属于附件功能，另开方案。
