# 方案：停止生成 + 断线重连

> 状态：方案稿，待审核，未写代码。

## 一、目标

补上聊天 App 的两个基本盘：
1. **停止生成**：AI 长回复流式输出时，用户能打断（对应 DSH 的 `session/cancel`）。
2. **断线重连**：WebSocket 断开（熄屏、切网络）后自动重连并恢复状态，而不是现在这样只 toast 一次「连接已断开」。

---

## 二、停止生成

### 协议事实（已确认）

`session/cancel` 参数只有一个字段，返回也很简单：

```ts
// 请求
{ sessionId: string }
// 返回
{ accepted: true }
```

### 实现步骤

1. `client.ts` 加 `cancelSession(sessionId)` → 调 `session/cancel`。
2. `chat.vue`：
   - 发送按钮在「AI 正在流式输出」时变成「停止」按钮（或旁边加一个）。
   - 点停止 → `cancelSession(sessionId)` → 本地把 live 流标为结束。
3. 状态判断：`liveStream` 非空且未 done 时显示「停止」。

### 待确认

- cancel 后 `follow` 流会收到什么收尾帧（`assistant-stream` 的 `end` with `outcome !== 'committed'`？还是 `event`？）——决定停止后气泡怎么收尾（保留已输出的文字 + 标「已停止」）。

## 三、断线重连

### 现状

`ws.ts` 的 `followSession` 在 `onClose` / `onError` 时只调 `finish()`，`chat.vue` 收到 `onDone` 后 toast 一次就完事。

### 实现步骤

1. **重连逻辑**（改 `ws.ts`）
   - `onClose` / `onError` 时不直接结束，而是触发**带退避的重连**：1s → 2s → 4s …（封顶如 30s）。
   - 重连 = 重新 `uni.connectSocket` + 重新 `open` 流（复用 `followSession` 的 open 逻辑）。
   - 提供「手动重连」按钮（重连多次失败后显示）。

2. **状态恢复**（改 `chat.vue`）
   - 重连成功后，`follow` 会重新下发 `snapshot`（历史快照），用它重建 `bubbles`，覆盖断线期间可能漏掉的消息。
   - 断线期间用户还能发消息吗？倾向：**断线时禁用发送**（明确状态，不赌「发了能到」）。

3. **生命周期**
   - 页面 `onUnload` 时停止重连、关 socket（现有 `cancelFollow` 保留）。
   - App 后台（`onHide`）是否断开？倾向：先不断（保持简单），二期再考虑省电。

### 待确认

- `follow` 的 `open` 是否支持「从某个 seq 续传」（`throughSeq`/`beforeSeq`）？若支持，重连可以只拉增量，不必每次全量 snapshot。倾向：一期直接用 snapshot 全量恢复，简单可靠。

---

## 四、两份方案的公共点

- 都需要 `ws.ts` 把「连接生命周期」从「一次性」改成「可重试」：现在是 `task = uni.connectSocket(...)` + 一次性回调，要抽成可复用的「连接 + 重连」状态机。
- 建议一起做（都是 ws.ts + chat.vue 的改动），一次联调。

## 五、边界

- 一期：停止生成 + 指数退避自动重连 + 断线禁用发送 + 重连后 snapshot 恢复。
- 不做：断点续传（增量 seq 续传）、后台保活、多 tab 同步。
